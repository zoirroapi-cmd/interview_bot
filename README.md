# Interview Bot

Telegram-бот для подготовки к DevOps-собеседованиям. Пользователь выбирает вопрос, отвечает своими словами и получает эталонный ответ, техническое сравнение и оценку от ИИ.

Бот работает на Python 3.12, aiogram 3, PostgreSQL, Docker Compose и GigaChat.

## Возможности

- Выбор темы и режима: случайные вопросы, вопросы по порядку или случайный вопрос из всего банка.
- Повторение отвеченных вопросов: по теме, случайно или по порядку. Сначала предлагаются вопросы, срок повторения которых уже наступил.
- Проверка свободного ответа. Бот показывает оценку от 0 до 10, краткий эталонный ответ и сравнение с ответом пользователя.
- Оценка касается технического содержания. Промпт просит модель не оценивать грамматику, орфографию, опечатки, пунктуацию, стиль или структуру речи.
- Прогресс: XP, серия дней, дневная цель и число вопросов, решённых за день.
- Напоминания в выбранное время и часовом поясе.
- Сохранение ответов и результатов в PostgreSQL.

## Как устроена оценка

GigaChat получает вопрос и ответ пользователя и возвращает JSON с тремя полями: `reference`, `comparison` и `score`. Оценку выставляет модель; приложение ограничивает её диапазоном 0–10 и использует для XP и повторения.

Оценка переводится в уровень уверенности так:

| Оценка | Уверенность | Повтор через |
|---|---:|---:|
| `score < 3` | 1 | 1 день |
| `3 ≤ score < 5` | 2 | 1 день |
| `5 ≤ score < 7` | 3 | 3 дня |
| `7 ≤ score < 9` | 4 | 7 дней |
| `score ≥ 9` | 5 | 14 дней |

### Техническое примечание

В базе есть `questions.key_points`. Если у вопроса ещё нет тезисов, перед проверкой ответа бот генерирует их и сохраняет. Сейчас `evaluate()` не использует эти тезисы для выставления оценки: видимый пользователю формат — эталон, сравнение и общая оценка модели. Поэтому первая проверка нового вопроса может сделать дополнительный вызов GigaChat. Это место стоит привести в соответствие с выбранной моделью оценивания.

Если проверка ИИ не удалась, ответ сохраняется без оценки. Бот сообщает об этом и позволяет продолжить работу.

## Архитектура

```text
Telegram ──► aiogram / app.main ──► GigaChat
                    │
                    └──► app.db ──► PostgreSQL
```

- `app/main.py` — команды, меню, состояния диалога, настройки, повторение и напоминания.
- `app/llm.py` — авторизация и запросы к GigaChat, промпты и разбор ответа.
- `app/db.py` — SQL-запросы, сохранение ответов и прогресса; несколько простых миграций выполняются при старте.
- `init.sql` — начальная схема базы данных.
- `scripts/import_questions.py` — импорт банка вопросов из CSV.
- `scripts/generate_all_keypoints.py` — предварительная генерация тезисов для вопросов.
- `tests/test_llm.py` — тесты разбора оценки и вспомогательной логики.

В PostgreSQL хранятся темы, вопросы, пользователи, прогресс повторения и попытки. Попытка включает текст ответа, отзыв ИИ, оценку и дату.

## Банк вопросов

Первоначальный источник вопросов — [Swfuse/devops-interview](https://github.com/Swfuse/devops-interview). Локальные CSV в `data/` игнорируются Git и в репозиторий не попадают.

Импортер требует колонки `Тема` и `Вопрос`. Приоритет можно указать текстом `Приоритет 1` в любой колонке строки; если он не найден, используется приоритет 2.

Пример CSV:

```csv
Тема,Вопрос,Заметка
Linux,Что такое процесс?,Приоритет 1 — база
Docker,Чем контейнер отличается от виртуальной машины?,Приоритет 2 — база
```

Повторный импорт не дублирует тему и вопрос с тем же названием и текстом; при совпадении обновляется приоритет. Порядок вопросов по теме следует порядку записей в базе, поэтому импортируй CSV в нужной последовательности.

## Быстрый старт

Нужны Docker и Docker Compose v2. Создай `.env` и укажи в нём действительные значения вместо примеров из `.env.example`:

```bash
cp .env.example .env
```

Обязательно заполни `BOT_TOKEN`, `GIGACHAT_AUTH_KEY`, параметры PostgreSQL и соответствующий им `DATABASE_URL`. Подготовь `data/questions.csv`, затем выполни:

```bash
docker compose up -d db
docker compose run --rm bot python -m scripts.import_questions /data/questions.csv
docker compose up -d --build bot
docker compose logs -f bot
```

Повседневные команды в боте: `/start` или `/menu` открывают меню, `/settings` открывает настройки дневной цели и напоминаний.

## Настройки

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | параметры PostgreSQL в Compose |
| `DATABASE_URL` | строка подключения приложения; внутри Compose хост — `db` |
| `GIGACHAT_AUTH_KEY` | ключ авторизации GigaChat |
| `GIGACHAT_MODEL` | модель GigaChat; если не задана, код использует `GigaChat-2` |
| `GIGACHAT_VERIFY_SSL` | `true` включает проверку сертификата; при отсутствии переменной код использует `false` |
| `BOT_TZ` | часовой пояс для дневной цели и напоминаний; по умолчанию `Europe/Moscow` |
| `TELEGRAM_PROXY` | необязательный прокси для запросов к Telegram |

Образ устанавливает корневой сертификат Минцифры для запросов к GigaChat. В типовой конфигурации `.env.example` задаёт `GIGACHAT_VERIFY_SSL=true`. Не отправляй `.env`, токены, ключи и дампы базы в Git или чат.

## Деплой и эксплуатация

Production использует сервисы `bot` и `db` через Docker Compose. После обновления проверенного кода в каталоге проекта пересобери бота и проверь состояние сервисов:

```bash
docker compose up -d --build bot
docker compose ps
docker compose logs --tail=100 -f bot
```

Если серверу нужен прокси для Telegram, укажи его в `TELEGRAM_PROXY`. GigaChat вызывается напрямую и эту настройку не использует.

Создать дамп PostgreSQL:

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup_$(date +%F).sql
```

Дамп содержит пользовательские ответы и идентификаторы. Храни его вне репозитория в защищённом месте.

## Разработка и CI

Локально установи зависимости и запусти тесты:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q
```

CI в GitHub Actions запускает Ruff, pytest и сборку Docker-образа для `main` и `develop`.

## Что стоит решить дальше

Сейчас код генерирует эталонные тезисы, но общую оценку считает по отдельному промпту без передачи этих тезисов. Следующее продуктовое решение — выбрать и последовательно реализовать один из вариантов:

1. **Оставить нынешний формат:** эталонный ответ, техническое сравнение и общая оценка от модели; убрать ненужную генерацию тезисов из обычной проверки.
2. **Вернуться к оценке по тезисам:** передавать эталонные тезисы модели и показывать, что раскрыто, упущено или противоречит ответу, с оценкой по этому разбору.

После выбора стоит закрепить поведение тестами и проверить его на тестовом боте, прежде чем выпускать в production.
